Behavior & Logic
Client list source
Reads from portal:clients. Loaded on mount. Client count in header is live.
Active vs Pending badge
Badge color reflects cl.activated: green if true, gray if false. Pending = invite code issued, not yet redeemed.
View Portal button
Mounts the full ClientPortal for that client with a "COACH VIEW" badge in the top bar. Read/write — coach can edit on the client's behalf. The portal's Logout button returns to this list rather than ending the session.
Delete
Confirm dialog. On confirm, removes from portal:clients. Note: the client's entries (portal:e:<id>) and budgets (portal:budgets:<id>) are not cleaned up.
+ New Client
Opens a modal (see Create Client Modal section below).
Empty state
If clients.length === 0, shows "No clients yet." card. (In practice, demo seed always provides 3.)

Behavior & Logic
Required fields
Company Name, Email, and Industry. Save throws an alert if any are empty.
Industry dropdown
Two optgroups: "Standard" (the 7 hardcoded industries) and "Custom" (whatever Coach has defined in the Industries tab — only shown if at least one exists).
KPI Defaults section
Only renders after an industry is picked. Pulls defaults from getIndKpiDef(industry, customIndustries). Toggles let coach override. Custom industry with zero KPIs configured shows "No optional KPIs configured" message.
Industry change resets KPI toggles
Picking a different industry replaces the toggle states with that industry's defaults. Any manual overrides are lost.
On Save
Builds new client object with: random id, captured fields, KPI toggles, random 6-char invite code (uppercase), activated:false. Appended to portal:clients. Modal closes.
Default client shape
Spread of defClient(): capacityMethod='manual', empty arrays for employees/departments/customKpis/capacityGroups/hiddenKpis, weeklyHoursPerFTE=40, slotDuration=30.

Behavior & Logic
Storage
Persisted at portal:custom_industries. Loaded once at App init, passed down through CoachAdmin and ClientPortal as customIndustries.
Two modes: list / edit
Local component state toggles between viewing list and editing one industry. New / Edit / Cancel switch modes. No separate route.
Editable KPIs only
Only non-auto, non-always KPIs (excluding efficiency) appear as toggles. Revenue / COGS / Gross Profit / GP Margin are always on for every industry and aren't shown here.
Categories shown
Marketing, Sales, Operations, Team. ("Overall Company" is filtered out — no KPIs live there.) Each category is its own grouped section.
Save flow
Save validates name (required). New industries get id ci_<random>. Existing ones keep their id. Save → 1-second "Saved ✓" → returns to list.
Delete
Confirm dialog. Existing clients tied to that industry are NOT affected (they keep the industry name string and use ALL_KPIS_DEF as fallback if the industry no longer resolves).
List card preview
Each card shows: industry name, count of active KPIs, and one badge per category listing which KPIs are on in that category. Empty cards (zero KPIs active) just show the count.
Planned Changes (for rebuild)
Remove the 7 standard industries
Drop IND_DEF and the INDS array entirely. All industries are coach-defined. The Industry dropdown in Create Client + Settings shows only what the coach has built. No "Standard" optgroup — single flat list (or just the items, no grouping needed once Standard is gone).
Implications: (1) Empty state for the Industry dropdown when no industries exist yet — needs to point coach to the Industries tab to create one. (2) Demo seed clients (ABC Autobody, Doc's Auto Clinic, Demo Company) will need their industries created as custom industries first, or seed will need to also create the industries. (3) getIndKpiDef() simplifies — no built-in lookup, just custom industries + fallback to all-off defaults. (4) The industry-specific label overrides in IND_LABELS (Healthcare's "Appt Fill Rate", Construction's "Labor Utilization", etc.) need a new home — either store labels on the custom industry record itself, or drop the relabel feature entirely.
Replace Delete with Archive (no permanent delete)
Remove the Delete button on client cards entirely. Replace with Archive. Archiving never destroys data — entries, budgets, capacity groups, and custom KPIs are all preserved in storage and restorable.
UX: Toggle at top of Clients page — "Active (N) | Archived (N)". Switches the list. Active cards show Archive; archived cards show Restore. No separate page.
State: New field on the client record, e.g. archived: true/false (default false). Archive sets it true; Restore sets it false.
Applies to: Both Active and Pending clients. Archiving a Pending client renders the invite code inert until restored.
Login behavior: Archived clients cannot log in. Login lookup must filter out archived === true records (in addition to the existing activated === true check). On restore, login works again immediately.
Coach view: Coach can still "View Portal" on an archived client (read all their historical data) — archive only affects the client's own access.
Resolves Gap: The current Gap "deleting a client doesn't cascade-delete their entries or budgets" disappears — nothing is being deleted, so no cascade needed.
Industries referenced by ID, not name
Today, each client record stores its industry as a string (e.g. "Construction / Trades"). Renaming an industry doesn't update existing client records, so they silently lose their KPI defaults link. With all industries becoming custom (per planned change above), this gap is more important — every client record needs to reference the industry by stable ID, not name.
Storage: Custom industries already have an id field (ci_<random>). Client record stores industryId instead of industry (string).
Display: UI looks up the current name from the industry list at render time. Rename flows through automatically.
Deletion safety: Deleting an industry that has clients pointing at it — confirm dialog with list of affected clients, or block until clients are reassigned. Coach's call.
Resend / regenerate invite code
Today, an invite code is generated once at client creation. If the client never received it (lost email, etc.) there's no recovery. Add an action on each Pending client card to regenerate the invite code.
UX: "Regenerate Code" button on Pending client cards (Active clients don't need one — they're already activated). Confirmation: "This will replace the current code ABCAUT. The old code stops working."
Storage: Overwrites client.inviteCode with a new 6-char code.
Display: The new code appears on the card, ready to be relayed to the client (text, email, in-call). Coach handles the actual delivery — no email infrastructure in the portal.
Resend (no regenerate): Same code can be re-relayed without regenerating; the code is always visible on the card. "Regenerate" is the action when the code is compromised, lost, or just stale.
Per-client current-week entry status on the Clients list (sister to Doc 03 no-entry indicator)
Surface entry status for each client directly on the Coach Admin Clients list — so the coach can see, at a glance, which clients are missing their current-week entry without clicking into each portal individually.
Where: a small pill on each client card, alongside the existing Active / Pending and invite-code badges.
States: "Current" (green) when an entry exists for the current week. "Overdue" (red) when the current week has no entry. Pending clients (not activated) don't show this pill.
Logic: a current-week entry is one whose startDate matches the current week's anchor (Sun–Sat per the week-change planned change below). Reads portal:e:<clientId> per client.
Sort: Clients list could optionally let the coach sort by status (overdue first) — useful for end-of-week review. Not required for v1.
Cross-doc: Doc 03 origin — the in-portal Entry Overdue pill and banner. Doc 06 — the Weekly Entry no-entry banner. This is the multi-client equivalent.
Sun–Sat week change (carry-forward from Doc 08)
Portal-wide week boundary changes from Mon–Sun to Sun–Sat. See Doc 08 for the source-of-truth decision and full cross-doc impact list.
Doc 02 impact: the per-client current-week entry status pill (above) anchors on Sunday instead of Monday. currentMonday() usage in any Coach Admin status logic becomes currentSunday().
Coach Admin top bar: unaffected by the Doc 03 top-bar rebalance (Coach Admin keeps the current top bar — there's no single client context on the Clients / Industries pages).
Note: current code behavior (above) is unchanged for now. These are notes for the eventual rebuild, not edits to apply today.
