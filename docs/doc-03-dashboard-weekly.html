Variant · Coach View (accessed via "View Portal")
The Good Plans Co ABC Autobody
COACH VIEW Dashboard Weekly Entry Budget & Goals History Settings Back
Page body is identical to the Client View above — same KPI grid, same tiles, same goal coloring, same notes block. Coach has full read/write access to entries, budgets, settings.
Differences from Client View
(1) Yellow COACH VIEW badge in the top bar.
(2) Logout button reads Back and returns to the Coach Admin Clients list rather than ending the session.
(3) Everything else identical — same data, same controls, full write access.
How it's reached
Coach Admin → Clients tab → "View Portal" button on a client card. Coach session is preserved; no separate auth.
Behavior & Logic
Which entry is shown
First, looks for an entry with startDate === currentMonday(). If none, falls back to the most recent entry by date. Date label says Most Recent Entry in either case.
▲▼ Delta arrows
Compared against the entry whose startDate is exactly 7 days earlier than today's Monday — not "the previous saved entry." If there's a gap, no delta shown. Hidden in cumulative modes.
Which KPIs are tiles
getEnabledKpis(client) returns: all always:true KPIs (Revenue, COGS, GP, GP%) + any toggled-on per client.kpis[id] + auto-derived KPIs whose dependencies are toggled on (e.g. Conversion Rate needs both Leads & New Clients on). COGS tile is always hidden — it's an input, not a tile.
Auto / derived KPIs
Gross Profit = Revenue − COGS. GP% = GP ÷ Revenue. Conversion = New Clients ÷ Leads. Avg Transaction = Revenue ÷ Transactions. Avg Repair Order = Revenue ÷ Jobs (Construction only). Avg Pipeline Deal = Pipeline Value ÷ Pipeline Deals. Revenue per New Client = Revenue ÷ New Clients. Avg Estimate Value = Estimates $ ÷ Estimates #. Sales Close Rate (Construction) = Contracts $ ÷ Proposals $.
Healthcare & Construction relabels
Healthcare: "Leads" → "New Clients Scheduled", "Employee Utilization" → "Appt Fill Rate" (and the Util tile is suppressed entirely).
Construction: "New Clients" → "New Contracts (#)", "Employee Utilization" → "Labor Utilization".
Sales is split 3 ways
Main (Contracts Won, Close Rate, Rev/Client, etc.) → Estimating subsection (Estimates Written, Target $, Avg Estimate) → Pipeline subsection (Pipeline Value/Deals/Avg). Each subsection has its own gray header rule. Other categories don't have subsections.
Tile color rules
Standard KPIs: green if actual ≥ goal (or ≤ goal for inverted), red if not. No goal → gray border, no color.
Range KPIs (Accounts Receivable): green if within ±10% of goal, red if outside.
"Achieved!" badge: top-right when goal is met (any non-range KPI with a goal).
Capacity group tiles (Team)
If client.capacityGroups has any groups, they replace the global Employee Utilization tile. Each group renders one tile with its own utilization % (calculated per its method: manual, slots, labor hours, etc.). Goal coloring is "within ±10% of target %" for non-dollar groups, "actual ≥ goal $" for dollar-based groups.
Weekly goal calculation
From getEntryGoal(id, entry, budget):
Revenue: month's adjusted goal × (entry.days ÷ days in month).
COGS: entry.revenue × cogsTargetPct.
GP: revenue goal × (1 − cogsTargetPct).
GP%: 100 − cogsTargetPct (constant).
Other count/$ KPIs: monthly goal × days ÷ 30.
% / avg / last KPIs: monthly goal as-is.
Inverted KPIs (lower is better)
COGS, Cancellations, Warranty / Returns. Plus any custom KPI the coach flagged as "Lower Better." Color logic flips: green if actual ≤ goal.
Notes block
Renders only if the displayed entry has a non-empty notes field. Light card style (different from the dark KPI tiles) to make it read like commentary.
Empty state
If the client has zero entries, the entire KPI grid is replaced with the "No entries yet" card. Mode pills (Weekly/MTD/QTD/YTD) are still visible.

Additional Tiles That Can Appear (beyond standard KPIs)
Custom KPI tiles
Each client can define unlimited custom KPIs in Settings → Custom KPIs. Each can be Count / Dollar / Percent format, placed in any category (Financials, Marketing, Sales, Operations, Team, Overall Company), with Higher Better or Lower Better direction. They render alongside standard KPIs in their assigned category. Stored on the client record at client.customKpis. No upper limit.
Capacity group tiles (Team category only)
When client.capacityGroups contains any groups, the standard Employee Utilization tile is replaced with one tile per group. Each group has its own tracking method (manual %, by time slots, by labor hours, by working hours, by revenue $, by headcount) and its own goal. Tile renders as utilization % with a progress bar and method label. ABC Autobody = 2 groups (Production Crew + Sales Team). Doc's Auto Clinic = 1 group (Service Technicians). No upper limit.
"Overall Company" category exists but is empty
Listed as a category in CATS but no standard KPI is assigned to it. Custom KPIs can be placed there. Otherwise the entire category section is hidden (no header rule, no empty state).
Planned Changes (for rebuild)
Drop "Lower is better" subtitle on inverted KPIs
Inverted KPIs (Warranty/Returns, Cancellations, COGS, and any custom KPI flagged "Lower Better") currently show an italic "Lower is better" subtitle under the tile name. Remove that subtitle. The KPI stays inverted — green-when-lower color logic continues to apply — just no text label.
Drag to reorder dashboard (per-client)
Each client can rearrange their own dashboard. Order persists per-client (saved to client record).
Categories: Financials is locked at the top — not draggable. All other categories (Marketing, Sales, Operations, Team, Overall Company) can be reordered up/down freely.
Subsections: Estimating and Pipeline (within Sales) can reorder up/down within Sales only. They can't move out of Sales.
Tiles: Can reorder within their parent section/subsection only. No cross-category moves (e.g. you can't drag New Clients out of Marketing into Sales).
Storage: Order saved on the client record — likely a dashboardOrder object holding category order, subsection order per category, and tile order per section.
Reset: Should have a "reset to default order" affordance for clients who get lost.
Drop "Target $" from "Estimates Written" tile name
Current label: "Estimates Written – Target $". New label: just "Estimates Written ($)" or "Estimates Written" with a $ format indicator. Just dropping the words "Target $" — the underlying KPI doesn't change. The companion "# of Estimates Written" KPI is unchanged.
Re-balance the top bar — client first, branding to footer
Current top bar leads with "The Good Plans Co" and shows the client company name as a small subtitle. Flip the visual hierarchy: client company name becomes the primary title in the top bar, prominent and clearly identifying whose portal you're in. "The Good Plans Co" branding moves out of the top bar entirely and lives in a small footer at the bottom of every page (or a discreet corner mark).
Rationale: When a client is logged in, this is their portal — the visual emphasis should reinforce that. Coach branding stays present (footer) but doesn't compete with the client identity for attention.
Applies to: Top bar across all client-facing pages — Dashboard (all 4 modes), Weekly Entry, Budget & Goals, History, Settings. Coach Admin pages (Clients list, Industries) keep the current top bar since there's no single client context.
Coach View consideration: When a coach is viewing a client's portal via "View Portal," the top bar shows the client's name as primary too — combined with the COACH VIEW badge, this makes it clear the coach is operating inside that client's space.
Footer treatment: Small text, low-key. Could include "Powered by The Good Plans Co" or just the wordmark. Not a full footer with nav — just a brand mark.
No-entry indicator when the current week is missing
When no weekly entry exists for the current week (Monday–Sunday), surface it visibly on the dashboard so the client and coach both notice the gap immediately. Two layers:
Inline pill (always present): the existing header pill (currently "Most Recent Entry · [date]") becomes a two-state element. Fresh state: reads "Week of [date]" with neutral styling when the current week's entry exists — tighter, less redundant than "Most Recent Entry" once the no-entry case is handled separately. Stale state: turns red and reads "⚠️ Entry overdue · last entry [date]" when no current-week entry exists. Same pill, two states, no extra real estate.
Banner: a slim red strip at the top of the dashboard: "Weekly entry overdue — your portal can't reflect this week until you log it." Includes a "Go to Weekly Entry" button. Dismissible per-session but reappears on next load if still overdue.
Logic: a current-week entry is one whose date falls within this Monday → Sunday. Indicator clears the moment one is saved. Applies to Weekly mode only — MTD/QTD/YTD modes don't show the indicator since they're cumulative views.
Coach view: same indicator visible. When the coach drops into View Portal on a client, the inline pill and banner both show — useful pre-session check. The sister planned change on Doc 02 (per-client entry status on the Clients list) handles the multi-client overview so the coach doesn't have to click into each portal individually.
Rationale: Weekly entry is part of the coaching contract, not something the product engineers around. But making the gap visible — to both parties — turns "you forgot" into a fast, low-friction nudge instead of a coaching conversation.
Coach notes block on the dashboard
A single persistent block on the dashboard where the coach leaves standing context for the client — focus areas, action items from sessions, strategic heads-ups. Coach edits, client reads. Not tied to a specific week — the coach updates it as the relationship evolves.
Position: top of the dashboard, above the KPI tiles. Prominent placement — frames the numbers below it as the first thing the client sees on login.
Editing: coach-only write access via Coach View. Click into the block to open an inline editor; save persists to the client record. Plain text with line breaks (no rich formatting in v1 — keeps the rebuild simple).
Display to client: read-only. Includes a small "Updated [date]" timestamp so the client knows when the message was last refreshed.
Empty state: when no note exists, the block is hidden in client view (a fresh client doesn't see an empty card). In Coach View, shows a subtle "Add a note for [client]…" prompt so the coach can start one.
Length handling: shows up to ~3 lines / ~300 characters by default with "Read more" to expand. Prevents a long message from pushing the KPI grid below the fold.
Storage: new field on the client record, e.g. coachNote: { body: string, updatedAt: timestamp }. Single value — no history/versioning. If session-by-session history matters later, that's a separate "Notes & Sessions" page, not part of this change.
Access pattern: follows the same coach-edit / client-read split as Settings (per Doc 04 #7) and the per-client entry-status logic in Doc 02. Consistent permissions model across the portal.
Applies to: Weekly mode dashboard for v1. MTD/QTD/YTD modes can inherit the same block in the cumulative-modes doc when we get there — likely just renders identically since the note is a property of the client, not the period.
Sun–Sat week change (carry-forward from Doc 08)
Portal-wide week boundary changes from Mon–Sun to Sun–Sat. See Doc 08 for the source-of-truth decision and full cross-doc impact list.
Doc 03 impact: Most Recent Entry indicator anchors on the current Sunday instead of the current Monday. Week-over-week delta lookup changes from "exactly 7 days earlier than today's Monday" to "exactly 7 days earlier than today's Sunday."
No-entry indicator: the "current week" definition for the Entry Overdue pill / banner becomes Sun–Sat. An entry is "current" when its startDate matches the current week's Sunday anchor.
Helper functions: currentMonday() usage replaced with currentSunday(); prevMonday derivation in DashView shifts by one day.
Note: current code behavior (above) is unchanged for now. These are notes for the eventual rebuild, not edits to apply today.
