Why History is read-only
History is a review surface, not an edit surface. To change a value, the coach (or client) navigates to Weekly Entry, picks the date, and edits it there. Keeps the data-entry path single and unambiguous.
Behavior & Logic
Default date range
On page load, From Date defaults to nWeeksBack(11) — the Monday 11 weeks before today. To Date defaults to currentMonday(). Together that's the last 12 weeks (today's Monday and the 11 prior Mondays). Both pickers accept any date — past or future — with no constraints. Future dates that don't yet have entries simply produce empty columns; the page handles that gracefully.
Date range filter
An entry is included if its startDate is between From and To, inclusive (string comparison on YYYY-MM-DD). Filter is by entry start date only — the entry's full span (e.g. a 7-day entry starting near the From boundary) is not considered.
Column sort order
Date columns are sorted ascending by startDate — oldest on the left, newest on the right. Reads naturally as a timeline.
Which KPI rows appear
One row per enabled KPI, plus one row per custom KPI. Starts from getEnabledKpis(client) and excludes: cogs (HIDE_TILE_IDS), laborHoursCompleted (SKIP_CUM), and employeeUtilization when the industry is Healthcare / Wellness. Always-on auto KPIs (Gross Profit, GP Margin, Conversion Rate, etc.) appear with their calculated values.
Cell value
Each cell shows the entry's value for that KPI, computed via calcEntry(entry, client) and formatted to the KPI's format ($, %, or #). Missing or non-numeric values render as — with no background color.
Cell color logic
Each cell is compared to its per-entry weekly goal via getEntryGoal(id, entry, budget). If a goal exists: green (#7ED957) when at-or-above goal, red (#ff3131) when below. Inverted KPIs (cogs-flagged + custom dir:'lo') flip — lower is green. Range KPIs (Accounts Receivable) are green when within ±10% of goal, red otherwise. No goal → transparent cell, no color.
How weekly goals are derived
Revenue: monthly goal (or YTD-adjusted monthly goal) × (entry days ÷ days in that month). COGS / GP / GP Margin: derived from revenue goal × cogsTargetPct when set, else null. Other KPIs: monthly goal × (entry days ÷ 30), except %-format and avg/last-aggregation KPIs which use the monthly goal directly. Partial entries get smaller goals proportional to their day count.
Color key visibility
The green/red legend in the header only appears when the budget has goals defined — i.e. has a revenue goal, a COGS target %, or any entries in budget.goals. Without goals every cell is transparent, so the legend would be misleading.
Sticky KPI column
The leftmost KPI column is sticky-positioned (position: sticky; left: 0;) so KPI labels stay visible during horizontal scroll. Date column headers do not stick on vertical scroll — only the KPI column on horizontal scroll.
Partial-entry column headers
Full-week columns show just the short date — e.g. "Apr 20". Partial-period entries append day count — e.g. "Mar 9 (3d)". Helps the reviewer understand why a column's numbers are smaller without having to mentally lookup the entry.
Empty state
When the date range contains zero entries, the table is replaced by a centered card reading "No entries in this date range." The date range card and entry count line stay visible above so the user can adjust the range.
Read-only — no inline edit
No cell or row is editable. No save button. No row click handlers. Cells are display-only spans with background colors. To modify an entry, navigate to Weekly Entry and pick the corresponding date.
Notes not shown
Per-entry notes (the free-text field on Weekly Entry) are not rendered on History. The page is purely numeric. Notes only surface on the Dashboard (Weekly mode, most-recent entry) and on the Weekly Entry form itself.
No totals row, no aggregation
Each cell shows that single entry's value. There's no sum, average, or "total" column. For period-level views (MTD / QTD / YTD totals) the user goes to the Dashboard and switches modes — that's the cumulative-modes surface. History is per-entry only.
Team Capacity rows excluded
Per-person / per-team Team Capacity entries (teamCapacityRows) do not appear as rows on History. Only standard KPIs and custom KPIs are rendered. The teamCapacity master toggle, if enabled, contributes only the aggregate row.
Planned Changes (for rebuild)
Match Dashboard KPI rows
History currently applies cumulative-mode exclusion filters that don't belong on a per-entry view — laborHoursCompleted is dropped via SKIP_CUM; employeeUtilization is hidden when capacityMethod is non-manual. Align the History row set to match the Dashboard's Weekly-mode tile set: every KPI that renders as a tile on the Weekly Dashboard renders as a row here.
Drop SKIP_CUM exclusion: Labor Hours Completed becomes a row when the KPI is enabled — it's a per-week metric and belongs in a per-week view.
Drop the cumulative-mode employeeUtilization exclusion: that filter exists because cumulative util is meaningless across mixed-method weeks. Per-entry, it's just the week's number.
Keep: Healthcare/Wellness employeeUtilization exclusion (industry-level, applies on Dashboard too); HIDE_TILE_IDS exclusion of cogs (cogs is a behind-the-scenes input on Dashboard too).
Include Team Capacity rows: when client.kpis.teamCapacity is on, render one row per teamCapacityRow (person or team), formatted to the team capacity metric. Matches how the Dashboard renders these as group tiles in the Team category.
Custom KPIs: unchanged — one row each, ordered after standard KPIs in their category.
Why this matters: a coach reviewing weekly performance shouldn't see a different KPI list on Dashboard vs History — same data, same set, same labels.
Sticky headers — date row and KPI column
The KPI column sticks left during horizontal scroll, but the date header row scrolls out of view vertically once the table has more than a screen of rows. Make the date header row sticky-top in addition to the existing sticky-left KPI column. Both stay anchored during any scroll direction.
Date header row: position: sticky; top: 0;. Stays anchored as the table body scrolls vertically.
KPI column: position: sticky; left: 0; (already current).
Top-left "KPI" header cell: sticky in both directions, with a higher z-index than the row header and column header so it sits cleanly above both during diagonal scroll.
Backgrounds: all sticky cells get opaque backgrounds (matching the existing dark fill) so scrolling content doesn't bleed through.
Quick range preset buttons
Add a row of preset buttons next to the date pickers — one click sets both From and To. Saves manual date entry for the common review windows and makes the page faster for coaches reviewing many clients in sequence.
Presets: Last 4 Weeks · Last 12 Weeks (default) · MTD · Last Quarter (last full calendar quarter, not QTD) · YTD.
Behavior: clicking a preset sets both date fields and immediately re-renders the table.
Custom range still allowed: the date pickers stay editable. Once the user picks a date that doesn't match any preset, no preset is highlighted — it's a custom range.
Active preset: highlighted yellow when current From/To exactly matches that preset's range.
Default load: "Last 12 Weeks" is the active preset on page load.
Export to CSV / Excel
Add an export button that downloads the currently-filtered table data. Same row/column layout as the on-screen table — KPIs as rows, dates as columns. Useful for coaches assembling external reports and clients keeping their own records.
Default format: CSV. Opens cleanly in Excel, Numbers, Google Sheets.
Optional .xlsx: a second button if straightforward to add; not blocking. CSV alone covers the use case.
Filename: [Company] - History - [from] to [to].csv — e.g. "ABC Autobody - History - 2026-02-02 to 2026-04-20.csv".
Includes: all visible KPI rows in current filter state, all date columns in current range, raw values formatted to the KPI's format ($, %, #).
Excludes: color cells, the legend, page chrome. A separate column for goal value or pass/fail status — out of scope for v1, can be added later.
Notes: not exported in v1. Notes intentionally aren't on this page; if/when they're added, exporting them is a separate decision.
Coach view: available, identical output. Exported file is identical regardless of which view triggered it.
Hover tooltip — magnitude vs goal
Cell color tells direction (above/below) but not magnitude. A reviewer sees "off goal" but has to switch to Budget & Goals to know by how much. Add a hover tooltip showing the goal value and the gap, so the magnitude is one mouse-hover away.
Standard KPIs: tooltip reads "Goal: [value] · [+/−] [diff] ([+/−]X%)" — e.g. "Goal: $42,000 · −$2,000 (−4.8%)".
Range KPIs (Accounts Receivable): "Target: [value] ±10% · actual is [+/−]X% of target" — e.g. "Target: $20,000 ±10% · actual is +12.5%".
Inverted KPIs (cogs / warranty / cancellations / custom dir:'lo'): sign-flip the gap so positive always means "better than goal" — e.g. for Warranty/Returns "Goal: 1 · −1 (under by 1)" reads as a positive outcome.
Cells with no goal: no tooltip. Transparent cells stay quiet.
Touch devices: tap-to-show, tap-elsewhere to dismiss. Don't block table scroll.
Coach view: identical behavior.
